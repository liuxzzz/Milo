## 1. 现阶段可以使用的版本

**Milo｜个人投资助手 Agent（方案设计阶段）**

2026.11 — 至今｜个人项目

项目地址：[liuxzzz/milo](https://github.com/liuxzzz/milo)

**场景与职责：** 面向个人投资者持仓数据与研究资料分散、投资理由难以持续追踪的问题，规划自然语言驱动的投资工作台，串联持仓分析、公司研究、投资档案与按需复查。负责产品方案、全栈与 Agent 架构设计，明确八周开发范围及验收标准。

**技术栈（已选型）：** Agent：Mastra、Workflows、Tool Calling、MCP；前后端：Next.js / React、TypeScript / Node.js；数据与通信：PostgreSQL、Zod、SSE。

- **任务编排与账户数据：** 设计基于 Mastra Agents 与 Workflows 的任务链路，将账户查询、公司研究和理由复查拆为可校验步骤；通过 MCP 账户快照定义币种、数据时点与缺失状态，以 Zod 统一工具契约，明确金额、仓位等指标由服务端计算，模型负责分析与解释。
- **研究证据与结果校验：** 设计“资料检索—证据提取—研究综合—引用校验”流程，将关键事实关联原始来源、财务期间和原文位置；定义数值口径、资料冲突与信息缺失的处理规则，使研究结论具备可核查的依据。
- **投资档案与人机协作：** 区分会话记忆与正式投资档案，设计投资理由、关键假设和风险约束的版本模型；规划通过 Workflow 暂停与恢复承接用户确认，按需对照真实成交及新证据生成复查提案，以版本检查防止旧提案覆盖新判断。
- **任务恢复与质量评测：** 制定基于 PostgreSQL 的运行持久化方案，区分 SSE 断线续读与进程重启恢复，明确重试、取消及报告发布的业务幂等边界；规划结合 Mastra Scorers 与执行追踪的评测，覆盖财务数值、引用支持度、故障恢复及调用成本。

简历空间有限时可压缩为：

> 发起并完成个人投资助手 Milo 的 V1.0 方案设计及 TypeScript、Next.js、Mastra 架构选型，围绕 MCP 持仓数据、可追溯公司研究与投资理由复查制定八周实施路线，应用开发待推进。

## 2. 实现并验收后使用的目标文案

本节用于指导后续开发与取证。只有相应机制已经实现、演示或测试后，才将对应条目移入正式简历。技术栈已完成选型，正式简历仍按实际实现情况填写。

**Milo｜个人投资助手 Agent**

技术栈（已选型，待实现）：TypeScript、Next.js、Mastra、Node.js 常驻服务、PostgreSQL、MCP、Zod、SSE。

项目描述：

> 面向个人投资研究与持仓管理，开发集账户分析、公司研究、投资档案、仓位试算和按需复查于一体的全栈 Agent，将真实账户数据、研究证据和投资理由关联为可追踪的决策过程。

可选贡献条目：

1. **Agent 与数据工具。** 基于 Mastra Agent 与 Workflows 编排任务，通过 MCP 工具获取账户事实，以 Zod 定义数据契约，并由 Milo 自建确定性财务计算完成资产配置与仓位试算，明确数据时点、币种及缺失状态。
2. **研究与证据。** 构建公司研究和双公司对比流程，由 Milo 自建资料解析、证据索引、事实引用与证据支持校验，支持从研究结论定位到原始资料及财务期间。
3. **投资档案与复查。** 通过 Mastra Workflows 的 suspend/resume 等待用户确认投资理由；由 Milo 自建档案版本与按需复查机制，对照真实成交、事前理由和新证据生成提案，保留修改历史并处理并发版本冲突。
4. **执行可靠性与评测。** 基于 Node.js 常驻服务、Mastra Workflows 和 PostgreSQL 保存任务状态，以 Milo 自建的业务幂等及 SSE 事件续读处理重复执行与断线，支持失败重试和取消；结合 Mastra Scorers 与执行追踪评估输出质量、定位失败并记录模型调用、耗时和费用估算。

不需要一次使用全部四条。根据投递岗位选择最有源码和演示证据的三条，再补一条实际测量结果。
